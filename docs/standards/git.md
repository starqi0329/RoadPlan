# Git 规范

## 分支

分支名一律用英文小写、数字和连字符，不要用中文。

| 分支 | 谁用 | 说明 |
| --- | --- | --- |
| `main` | 组织者 | 只接收复核通过的内容 |
| `slice/1` | 组织者 | 一个切片的集成分支，用来复核和真机验收 |
| `fe/`、`be/`、`qa/` 开头 | 对应角色 | 例如 `be/s1-status-derivation` |
| `spike/` | 组织者 | 技术验证，不合进 `main` |

正确示例：`fe/s1-day-timeline`、`be/s1-plan-rules`、`qa/s1-acceptance`。  
错误示例：`fe/s1-计划时间轴`、`be/s1-状态推导`。

## 提交说明

提交说明一律用中文。第一行：

`类型(角色): 描述 [切片][功能编号]`

类型是 `feat`、`fix`、`test`、`refactor`、`docs`、`chore`、`contract` 之一。角色可以省略。冒号后面写中文，概括这次改动或这个文件做什么。

```
feat(be): 计划状态推导与时间门槛 [S1][FR-05]
docs: 所有 agent 的开工说明
contract: 契约升到 v0.3
```

`contract` 只能由组织者在 `main` 上使用。提交钩子会拒绝不合格式的说明。

## 提交要求

- 一次提交只做一件事，提交后项目能通过编译。
- 不要把纯格式调整和功能修改混在同一次提交里。
- 提交锁文件。不要提交 `node_modules`、`target`、`dist`、密钥。
- 每个切片提交汇报时，带上「给人看的产出」。有界面就把截图放进 `docs/reports/sN/`，文档里用相对路径。不要把截图留在本机其他目录。

## 禁止

强制推送、改写 `main` 的历史、修改别人的分支。

## 同步和合并

契约升级后，把 `main` 合并进自己的分支，不用变基。

一个切片的合并顺序是后端、前端、测试，先合进 `slice/N`。用户复核通过后，组织者再把 `slice/N` 合进 `main`，并打标签 `sN-approved`。

## 越界检查

提交时按分支前缀检查文件路径，越界直接拒绝。组织者分支不检查路径。

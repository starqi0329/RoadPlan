# 代码规范

界面文字用中文。代码命名用英文。注释只写代码本身看不出来的约束。

Git 相关约定：

- 新建分支用英文，例如 `be/s1-plan-rules`，不要用中文分支名。
- 提交说明用中文，概括这次改动做什么，格式见 `docs/standards/git.md`。

## 前端

- TypeScript 严格模式，不用 `any`。
- 只用函数组件。组件文件用大驼峰，例如 `PlanCard.tsx`。
- 调用后端只用 `src/bindings.ts` 里生成的 `commands`。不要手写命令名。
- 不在前端写业务规则。能不能完成、当前状态、算不算迟，都用后端返回的字段。
- 数据请求用 TanStack Query。收到 `data-changed` 事件后重新获取对应数据。
- 样式用 CSS Modules。颜色和间距放到 CSS 变量里，对照 `docs/prototype/`。
- 后端错误码在一处翻译成中文提示。

## 后端

- 必须通过 rustfmt。clippy 的警告按错误处理。
- 正式代码里不用 `unwrap` 和 `expect`。错误用 `AppError`。
- 分层：`domain` 放纯规则，不碰数据库和 Tauri；`commands` 只做参数转换。数据库和窗口控制在后续切片加入。
- 规则函数的"当前时间"由参数传入，不在规则里读系统时间。`get_now` 是唯一读系统时间的地方。
- 每个写操作和它的操作记录放在同一个数据库事务里。这个要求从接入数据库的切片开始执行。
- 已经提交的数据库迁移文件不能再改。

## 测试

- 测试名写清场景，例如"10:42 时 11:30 开始的计划不能完成"。
- 用固定时间，不在测试里等待真实时间流逝。
- 每个测试自己准备数据，不依赖执行顺序。

## 检查

`pnpm verify` 会跑类型检查、ESLint、Prettier、前端测试、rustfmt、clippy、Rust 测试和越界检查。

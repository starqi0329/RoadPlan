## 给人看的产出

### 这一阶段交出了什么

交出一份亲手核对清单，以及 3 条对照。要证明的是：点「最小化」和点「×」是两件事，都能反复做，也都能回到完整主窗。最小化去任务栏，关闭去托盘。只有托盘里的「退出」才真正关掉程序。

这 3 条现在只跑在对照上。后端和前端还没把这条正式路径合进来，所以还不能证明你这台电脑上的按钮已经分得清。

### 打开窗口能看到什么

这一阶段没有新的画面。顶栏上应能分清「最小化」和「×」，但整窗有没有真的消失、任务栏和托盘是不是各走各的，要等合入后在 Windows 上看。

### 点哪里、会发生什么

人要亲手点的步骤在 [真机验收.md](真机验收.md)。等后端和前端合进这条之后，在自己的 Windows 开发版上按那张表做。

对照已经写明这些事，真实命令接上之后用同一组说法再跑：

- 点最小化：程序还在，主窗不可见，记的是最小化，不是进托盘，也不是折叠。主窗的宽高不变。从任务栏恢复后，主窗可见，两种隐藏都清掉，仍然不是折叠。
- 点 ×：程序还在，主窗不可见，记的是托盘，不是最小化。已经在托盘时再关一次仍然成功。托盘「打开主窗」后，主窗回来。再点 ×，又进托盘。最后托盘「退出」，程序才结束。
- 先最小化，再用托盘「打开主窗」：主窗回来，不是最小化，也不是还停在托盘。接着再点 ×，仍然能进托盘。布局没有被收成折叠。

任务栏上有没有图标、窗口是不是只剩一条顶栏杠，只能人眼看。

## 需要人决定的问题

### 契约变更申请

- 提出人：测试
- 当前版本：0.3.2
- 缺什么：契约有 `hide_main_to_tray` 和 `quit_app`，没有「最小化」这个命令，也没有写它和托盘、折叠是三种状态。`show_main` 只写了从托盘或胶囊恢复，没有写能不能解除最小化。已经藏进托盘时再调一次 `hide_main_to_tray`，契约也没写该不该成功。
- 为什么现有字段不够：若把最小化做成 `set_main_collapsed`，窗口会留下一条顶栏。若把它做成 `hide_main_to_tray`，任务栏和托盘会走错。不把这三件事分开，第二次点 × 会不会失灵也无法核对。
- 建议的字段或命令：二选一写进契约。一是新增最小化命令，恢复用任务栏或同一条命令的反向操作；`show_main` 若被托盘调用，要写明会不会同时解除最小化。二是写明最小化只由界面调系统能力，后端不新增命令，但 `show_main` 必须能从最小化恢复。并写明主窗已经不可见时，再次 `hide_main_to_tray` 仍然成功。
- 会影响谁：顶栏「最小化」和「×」、托盘「打开主窗」、这组测试。

对照在契约补上之前，临时把最小化、托盘、折叠分成三种状态。已经在托盘时再关一次算成功。最小化之后点托盘「打开主窗」，算把主窗完整叫回来。若组织者规定托盘不能管最小化，这组对照再改。

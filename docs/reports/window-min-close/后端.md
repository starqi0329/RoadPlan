## 给人看的产出

### 这一阶段交出了什么

关掉主窗进托盘可以反复做，不会第二次就失灵。从托盘「打开主窗」时，就算窗被系统最小化了，也会先解除最小化再显示并聚焦。顶栏「最小化」应走新的后端命令（整窗进任务栏），不再靠「折叠成一条顶栏杠」，也不跟进托盘混成同一种隐藏。

### 打开窗口能看到什么

这一阶段没有新的窗口画面。用户能感到：× / 托盘开关更稳；最小化与进托盘是两回事。

### 点哪里、会发生什么

- 点 × 或系统关闭 → 只进托盘，进程还在；再打开再关仍进托盘。
- 托盘「打开主窗」→ 主窗回来并聚焦；若当时是任务栏最小化，也会被拉起来。
- 最小化（待前端改接 `minimize_main`）→ 整窗进任务栏，不是托盘，也不是顶栏杠。
- 主窗句柄丢了时，命令会报错，不再假装成功。

### 还没做什么

- 开机自启、提醒
- 前端去掉二次 `hide()` / 改接 `minimize_main`（属前端任务包）
- 契约正文尚未写入 `minimize_main`（等组织者按变更申请升版）

### 截图

这一阶段没有界面。

### 关闭拦截保留哪一层

**系统关闭**的权威拦截只在 Rust：`lib.rs` 的 `CloseRequested` → `prevent_close` + `hide_main_to_tray`。  
前端 × 应只调 `hide_main_to_tray`；hotfix 里 `closeMainToTray` 的二次 `win.hide()` 是垫步，合入后应由前端收掉，避免与 Rust 抢状态。`hide_main_to_tray` 已做成可重复，双调用也不应炸。

## 改了哪些文件

- `src-tauri/src/window_ops.rs`：`hide_main_to_tray` / `show_main` 找不到主窗 → `not_found`；`show_main` = `unminimize` + `show` + `set_focus`；新增 `minimize_main`（不碰 `mainCollapsed`、不写布局）
- `src-tauri/src/commands.rs`：接线 `minimize_main`

- `src/bindings.ts`：`pnpm bindings` 生成 `minimizeMain`

新增依赖：无。坏布局校验未改动。

## 需要人决定的问题

### 契约变更申请

- 提出人：后端
- 当前版本：0.3.2
- 缺什么：没有「系统最小化主窗」命令；现有 `set_main_collapsed` 是内容区折叠，`hide_main_to_tray` 是进托盘，都不能表达「整窗进任务栏、可从任务栏点回」。
- 为什么现有字段不够：前端若只调 Tauri `Window.minimize()`，最小化权威路径不在契约命令表里，前后端无法用同一套 bindings 验收；也不应复用折叠或进托盘。
- 建议的字段或命令：在 §3.6 增加 `minimize_main` → `void`（系统最小化主窗；不等于进托盘，不改 `mainCollapsed`）。恢复继续用已加强的 `show_main`（`unminimize` + `show` + `focus`），不另加 `restore_main`。可选补一句规则：最小化 ≠ 关闭进托盘 ≠ 胶囊。
- 会影响谁：前端顶栏最小化改调 `commands.minimizeMain`；测试真机清单；本分支已实现命令与 bindings，等组织者写入契约并升版后再合 `main`。

选的是任务包**方案 1**。

## 给人看的产出

### 这一阶段交出了什么

主窗关掉不再退出程序，会缩到系统托盘；托盘可以再打开主窗，也可以真正退出。置顶小窗和边缘胶囊可以单独打开或关掉，位置和显示状态会记在本机，下次启动还在。拖动窗口时会通知前端减弱透明效果（当前还没开系统亚克力，只留了可接的钩子）。

### 打开窗口能看到什么

这一阶段没有新的窗口画面（界面由前端接线）。后端负责系统级行为：托盘图标、多窗口创建与隐藏、布局读写。

### 点哪里、会发生什么

没有新按钮可点。用户能感受到的变化是：

- 点主窗关闭 → 窗口消失，托盘还在，进程不退出。
- 托盘菜单「打开主窗」或左键点托盘 → 主窗回来并聚焦。
- 托盘菜单「退出」→ 进程真正结束。
- 打开过的置顶窗 / 胶囊，关掉应用再开还会按上次是否显示、位置大小恢复（布局写入应用数据目录里的 `window-layout.json`）。
- 主窗、置顶窗、胶囊读同一后端；改计划等写成功后，已打开窗口仍会收到原来的 `data-changed` / `minute-tick`。

### 还没做什么

- 操作记录浏览（`list_audit` 仍返回未实现）
- 开机自启、系统提醒
- 亚克力 / 系统模糊本身（`set_dragging` 只发 `dragging-changed` 事件给前端）

## 改了哪些文件

- `src-tauri/Cargo.toml`、`Cargo.lock`：启用 Tauri 2 特性 `tray-icon`、`image-png`（托盘图标；**未改根 `package.json`**，托盘走 crate feature，不必根项目声明插件）
- `src-tauri/capabilities/default.json`：允许 `main` / `pin` / `capsule` 及窗口显示、隐藏、置顶、拖动等权限
- `src-tauri/src/window_layout.rs`：默认布局、校验、应用数据目录 JSON 读写；单测覆盖校验与序列化往返
- `src-tauri/src/window_ops.rs`：§3.6 全部窗口命令实现；启动时恢复布局；`set_dragging` 发 `dragging-changed`
- `src-tauri/src/commands.rs`、`lib.rs`：命令接线；托盘菜单「打开主窗」「退出」；主窗关闭拦截 → `hide_main_to_tray`；pin/capsule 关闭改为隐藏并持久化可见性
- `src/bindings.ts`：重新生成后无实质差异（类型与命令声明已在契约 0.3.0 冻结时就绪）

新增依赖：无（仅打开已有 `tauri` 的 feature）。

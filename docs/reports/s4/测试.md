# 汇报

- 角色：测试
- 分支：`qa/s4-window-acceptance`
- 契约版本：0.3.0

## 给人看的产出

### 这一阶段交出了什么

交出「窗口与托盘」的亲手核对清单，以及 6 条不碰桌面也能跑的对照。对照只检查布局长什么样、存下的位置下次还能读回来、关掉主窗不等于退出、折叠只改标记、已打开的窗口都会收到变更。

这 6 条现在只跑在按契约写的对照上。窗口命令还没合进来，这台机器也没有 Windows 桌面，所以还不能证明你打开的程序已经会进托盘、置顶、收成胶囊，或在重启后停在原地。

### 打开窗口能看到什么

这一阶段没有新的窗口画面。现在的程序还没有托盘、置顶小窗和边缘胶囊。置顶是不是压在别的软件上面、拖动时透不透明、松手后样子回不回来，都要人在 Windows 上看。

### 点哪里、会发生什么

现在点不到这些窗口。人要亲手点的步骤在 [真机验收.md](真机验收.md)。等后端和前端合进 `slice/4` 之后，在自己的 Windows 开发版上按那张表做。

对照检查已经写明这些事，真实命令接上之后用同一组说法再跑：

- 第一次读到的布局里，主窗有一块宽和高都大于 0 的区域。契约没有写具体像素，对照不去对第一次打开停在屏幕的哪一角。
- 存下一份位置再读，还是那一份。重新启动后，用的仍是这份存档。
- 关掉主窗时程序还在，主窗位置也不丢。再打开，主窗回来。只有退出之后，程序才结束。
- 折叠再展开，只改「是否折叠」，主窗的位置和大小数字不变。窗口实际变高变矮要人眼看。
- 置顶和胶囊可以标成打开再关掉。拖动开始和结束都不改已保存的布局。是不是始终在最上层、松手后透明回来，不在自动检查里。
- 主窗、置顶、胶囊都开着时，新写一条计划，三个都会收到变更。胶囊关掉之后，再写一条，它不再收到，主窗和置顶仍然收到。

### 还没做什么

- 6 条真实窗口命令全部跳过。
- 没有托盘、置顶、胶囊的截图，也没有在窗口里看关闭进托盘、位置保留和多窗刷新。
- 没有测开机自启、提醒、完整操作记录页。
- 没有把第一次打开的默认坐标写死。

这一阶段没有窗口壳界面，所以没有截图。

## 需要人决定的问题

契约变更申请（本分支没有改契约）：

1. 第一次打开时的默认位置没有写死。`get_window_layout` 只说缺省时用实现自己的默认几何。对照只检查主窗宽高是正数，以及「存档再读、下次启动仍是这份存档」。若希望自动检查锁住第一次打开的坐标和大小，需要把默认的 x、y、宽、高写进契约。
2. `data-changed` 的实体只有计划、目标、复盘、操作记录。保存布局、折叠、拖动算不算「写成功」，要不要发这个事件，载荷里写什么，契约没有写。对照只在写下一条计划时，核对当时已打开的窗口都收到，并且实体里有计划。

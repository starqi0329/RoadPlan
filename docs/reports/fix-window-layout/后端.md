## 给人看的产出

### 这一阶段交出了什么

主窗位置和大小的存档更稳了：以前可能被存成「高度只有几十像素」或「飞到屏幕外」，再打开就像空壳或消失。现在这类坏档启动时会回到正常默认大小；折叠或关进托盘时，也不会再把那种废尺寸写进下次要用的正常窗口大小。

### 打开窗口能看到什么

这一阶段没有新的窗口画面。用户能感到：杀进程再开、折叠再展开、关进托盘再打开，主窗都应是看得见的正常大小，而不是一条细缝或跑出屏幕。

### 点哪里、会发生什么

没有新按钮可点。用户能感受到的变化是：

- 若本机里已经有一份坏掉的窗口位置存档，下次启动会用默认位置和大小，不会再开出几乎没高度的窗。
- 折叠只记「是否折叠」；展开时用的宽高仍是上次合法的展开尺寸（主窗至少约 640×480）。
- 关进托盘不会把隐藏后系统给的奇怪坐标写进存档。

### 还没做什么

- 提醒、导出、开机自启、云同步
- 前端折叠壳样式（属前端热修任务包）

## 改了哪些文件

- `src-tauri/src/window_layout.rs`：主窗最小 640×480；坐标绝对值超过 10000 视为屏外；非有限值拒绝；坏档加载回退默认（不静默钳制数值）；补单测
- `src-tauri/src/window_ops.rs`：`set_main_collapsed` 只改标志；`hide_main_to_tray` 不写几何；`save_window_layout` 仍走校验，废几何写入会被拒

置顶窗最小 160×120，胶囊最小 40×80（胶囊本身较小）。未改契约：坏档当「不可用存档」回退默认，不是加载时自动钳制（避免改 R31 语义）。

新增依赖：无。

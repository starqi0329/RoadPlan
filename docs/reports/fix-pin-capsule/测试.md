## 给人看的产出

### 这一阶段交出了什么

交出一份亲手核对清单，以及 3 条对照。要证明的是：点「置顶」会出现一扇独立的置顶小窗，能关掉再打开；点「胶囊」会先出现边缘胶囊，再把主窗收进托盘；点胶囊能把主窗叫回来。打不开时要明确失败，主窗还在，不能两边都没了。

这 3 条现在只跑在对照上。后端和前端的修复还没合进来，所以还不能证明你这台电脑上已经能看见置顶窗和胶囊。

### 打开窗口能看到什么

这一阶段没有新的画面。真机上点过「置顶」和「胶囊」却没有副窗。浏览器里的演示浮层不算修好。是不是横条、是不是压在别的窗口上面，要等合入后在 Windows 上看。

### 点哪里、会发生什么

人要亲手点的步骤在 [真机验收.md](真机验收.md)。等后端和前端合进这条之后，在自己的 Windows 开发版上按那张表做。

对照已经写明这些事，真实命令接上之后用同一组说法再跑：

- 打开置顶：置顶标记打开，并且记成始终在最前。主窗还在，不是最小化，也不是进托盘，胶囊没有一起打开。关掉后再打开，仍然如此。主窗的宽高不被改掉。
- 点胶囊：先把胶囊显示成功，再把主窗收进托盘。胶囊还在，进程还在，不是最小化。点胶囊对应的「打开主窗」后，主窗回来，胶囊先留着，可以再单独收起。
- 下一次打开置顶或胶囊若失败：命令失败，置顶或胶囊都不会被标成已打开。主窗仍然可见，也没有进托盘。

拖不拖得动、小窗里有没有进行中的计划或一句空闲说明，只能人眼看。

## 需要人决定的问题

### 契约变更申请

- 提出人：测试
- 当前版本：0.3.3
- 缺什么：R31 的最小 640×480 写的是主窗。置顶若做成横条（高大约几十到一百多），套用主窗下限就会被拒绝。`show_pin` / `show_capsule` 失败时用哪个错误码，契约没写。点「胶囊」必须先显示成功再藏主窗，也只写在任务里，没有写进命令说明。
- 为什么现有字段不够：副窗尺寸沿不沿用主窗下限，会决定横条能不能保存。失败码不统一，界面提示和对照会对不上。先藏主窗再发现胶囊没开出来，用户会看到什么都没有。
- 建议的字段或命令：写明 R31 的宽高下限只约束主窗；置顶和胶囊各自的可用宽高另写，或写明副窗只要在屏内且是有限数即可。写明 `show_pin` / `show_capsule` 失败时的错误码。写明用户点胶囊时，只有 `show_capsule` 成功才调用 `hide_main_to_tray`，并且藏主窗不得把胶囊一起关掉。
- 会影响谁：置顶和胶囊的默认尺寸、失败提示、这组测试。

对照没有把置顶锁成某一组像素。失败只要求返回错误且错误码不是空的，没有指定是哪一个码。点胶囊按「先成功再藏主窗」来写；失败时主窗保持可见。

## 给人看的产出

### 这一阶段交出了什么

交出一份「计划与状态」的核对清单，外加一套用固定时间写成的检查。时间钉在 2026-11-26 10:42（东八区），和契约里的示例时刻一样。

这套检查现在只跑在一份按契约写的对照上，用来把规则说清楚。程序里的计划命令还是「未实现」，后端和前端都还没合进来，所以它还不能证明你打开的软件已经做到这些。

### 打开窗口能看到什么

这一阶段没有计划界面。现在打开程序，窗口标题是「时序」，正文是第 0 阶段骨架，只有一颗「读取当前时间」。看不到某一天的计划，也没有完成、跳过、改期这些按钮。

### 点哪里、会发生什么

现在没有计划按钮可点。人要亲手点的步骤写在 [真机验收.md](真机验收.md)。等这一切片的后端和前端合进 `slice/1` 之后，在自己的 Windows 上用开发版，把当前时间固定成 `2026-11-26T10:42:00+08:00`，再按那张表点。

对照检查已经写明这些事，真实命令接上之后会用同一组说法再跑一遍：

- 10:42 去完成 11:30 才开始的计划，会被拒绝，计划仍是未开始。
- 10:00–11:00 的计划可以完成，不标迟。09:00–10:00 的计划可以补完成，并标迟。过了结束时间不会自己变成完成。
- 只有还没处理的计划可以跳过。完成后可以撤销，状态按当前时间重算。
- 编辑改不了日期。没处理过的计划一改期，原计划变成已跳过，并写上「已改期到」那一天；新计划留在新的日期。已经完成或已经跳过的，原计划保持原样。
- 复制到另一天时，新计划没有完成结果、没有备注、也没有改期来源。
- 只有还没处理的计划可以删除。
- 时间叠在一起会指出另一条，但两条都保存。已跳过的不参与提示。
- 核心计划不选周目标，保存失败。填了一个不存在的周目标，也失败。
- 同一天的计划先按开始时间排，开始时间相同再按创建时间排。

### 还没做什么

- 没有在真实的计划命令上跑过。32 条真实命令检查全部被跳过。
- 没有关掉再打开的真机结果。持久化要等人在 Windows 上做，见真机清单最后几步。
- 没有当前计划高亮、时间线、空状态这些画面检查。窗口上还没有这些东西。
- 没有测目标、复盘、置顶、托盘、拖动。
- 没有测「核心计划成功挂上一个真实周目标」。本切片不提供建立周目标的命令，测试不能自己造一条目标。
- 没有断言 09:00–10:00 和 10:00–11:00 这种刚好接上的两段算不算重叠。契约没写，见下面的变更申请。

## 需要人决定的问题

### 契约变更申请

- 提出人：测试
- 当前版本：0.2.0
- 缺什么：两条计划的时间刚好首尾相接时，算不算重叠。例如 09:00–10:00 和 10:00–11:00。
- 为什么现有字段不够：状态用的是左闭右开，`[开始, 结束)` 里刚好到结束点不算进行中。重叠只写了「相交」，没有写相接算不算。两种理解都会和某一条现有的话打架，所以没有代选。
- 建议的字段或命令：在 R12 补一句。若与状态同一口径，写明按 `[开始, 结束)` 相交，首尾相接不算重叠。若相接也要提示，写明闭区间相交。
- 会影响谁：后端的重叠结果，前端的提示，这一组测试。

### 请确认，先按字面做了

完成时间刚好等于结束时间：状态已经是已过期（「不早于结束」），但「迟」写的是「晚于结束」。检查按这个字面：刚好到点可以补完成，不标迟；过了结束点再完成才标迟。若「刚好到点」也要标迟，需要改 R3 的用词。

空白备注：字段校验写了「去掉首尾空白后为空就等于没有备注」。新建和单独保存备注都按这一条。若单独保存备注要保留空格，请说明。

找不到计划时，错误里的 `entity` 契约只说是字符串，没有规定用 `plan` 还是「计划」。检查只要求它非空，并且 `id` 就是请求的那一个。
